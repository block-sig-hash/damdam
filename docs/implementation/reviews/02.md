## Findings and fixes

Locations describe the submitted code at `8bff956`, before review corrections.

1. **P2 — Date validation still mixed clocks and dropped issued-at enforcement.**
   `apps/api/app/auth/tokens.py:89` disabled `iat` without replacing its check;
   `auth/dependencies.py:55` and `auth/hto.py:111` still let PyJWT compare it to
   real time. Consumer future-issued tokens were accepted, while valid
   organization tokens with a forward application clock were rejected. Malformed
   and nonfinite NumericDates could escape as exceptions or go unchecked.
   Added a shared decoder for mandatory expiry and present issued-at/not-before
   claims. It rejects invalid dates and uses one application clock while
   preserving signature, audience, purpose and production UTC expiry checks.
   PostgreSQL-backed regressions cover clocks in 2000 and 2100, future issuance,
   invalid dates, stored expiry and organization email/access validation.

2. **P2 — Concurrent refresh requests could both issue a replacement pair.**
   `apps/api/app/auth/tokens.py:105` read the token without a row lock, then
   revoked it after checking the snapshot. Two sessions could both observe it
   unrevoked. Added `SELECT ... FOR UPDATE` and an explicit stored-owner check;
   revocation and replacement still commit atomically. A real PostgreSQL test
   coordinates two requests and widens the race during issuance: the submitted
   code accepts both, the corrected code accepts one and rejects the other.
   This inherited neighboring defect was fixed with the rotation review; it does
   not implement the broader identity redesign in chunks 06/07.

3. **P2 — A corrupt image could pass the new completeness gate.**
   `apps/mobile/scripts/validateScreenshots.js:88` returned success after
   inspecting only the signature, dimensions and trailing IEND marker. Images
   with damaged or entirely absent IDAT data passed. Added bounded full decoding
   and CRC validation using `pngjs`, a JavaScript development dependency.
   Regression tests preserve the header/end while corrupting or removing the
   pixel data. Both failed against the submitted validator and pass after repair.
   The updated validator also accepts the actual 32 iOS PNGs downloaded from
   September 8 run `34198388517`; that is historical capture evidence, not a new
   test of this branch's macOS timeout setting.

4. **P2 — The matrix parser disagreed with valid Maestro YAML.**
   `apps/mobile/scripts/screenshotMatrix.js:40` used line regexes that missed
   inline tags, quoted capture names, comments and nested captures. Ordinary
   changes could select the wrong platform matrix or silently omit expected
   captures. Use the declared `yaml` development dependency, validate literal
   capture names, and fail explicitly on unsupported nested runFlow/repeat/retry.
   Positive YAML and nested-flow rejection regressions fail before and pass
   after the change. Screenshot tests run in the Node Jest environment so YAML
   resolves its Node export rather than the React Native environment's browser
   export. No production mobile screen or native configuration changed.

5. **P3 — Evidence and lint scope needed correction.**
   The signature-tampering test changed the last base64url character, potentially
   touching only unused padding bits; it now changes the first signature
   character. The bitwise lint exception now applies only to the PNG test
   fixture's CRC calculation. `AGENTS.md` records the resolved supplemental
   Claude-workflow role. CI/spec comments no longer claim the validator needs
   no npm dependencies or that slow XCUITest startup is a proven root cause.
   `ci.yml` changes select dashboard as well as API/mobile/build jobs; dashboard
   checks were independently run. STATUS's contradictory NOT_STARTED heading
   is corrected by this review record.

The original route-clock fix, 300-second bounded iOS timeout, exact screenshot
matrix, documentation-link job and supplemental-review boundary are retained.
Keeping both JWT expiry and stored-row expiry checks is deliberate: they enforce
separate signed and persisted constraints, and the latter can invalidate a row
before the signed claim expires.
