  fresh reviewer found that `signingConfigs.release` could pass while
  `buildTypes.release.signingConfig` was rebound to debug. The guard now reads
  the effective Release build-type config and rejects a copied or rebound
  debug certificate, missing material and a fingerprint mismatch. CI uses a
  one-day throwaway JKS for the positive and negative local paths. No approved
  certificate is stored in the repository.
- **P2 — EAS-shaped callback compatibility was not proved.** An initial CI
  fixture attached a `tasks.whenTaskAdded` callback after evaluation; a second

  `storeFilePath` already finalized. The later fresh review observed that the
  fixture still did not reproduce EAS's exact script insertion point. It was
  removed rather than reported as proof. This is a **release compatibility
  risk**, not an observed EAS cloud-build result. The release owner must
  choose a compatible signing approach under an approved EAS project and
  inspect the actual AAB/IPA signatures.
- **P2 — CI coverage and portability.** The new signing script paths now
  trigger the mobile job. The first run called the script from the wrong
  directory; a later run lacked `rg` on the Ubuntu runner. Both were fixed.
  The final fresh reviewer found no remaining concrete blocker for the narrow
  preparatory scope before exact-head CI finished; that CI subsequently
  passed. Intermediate failing/cancelled runs are recorded in the
  [handoff](../handoffs/29.md), not counted as passing evidence.
