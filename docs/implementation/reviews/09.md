## Findings and fixes

1. **P1 — a terminal quote could be reopened in SQL.** The immutability trigger
   allowed any status-only update, including `redeemed` back to `issued`. It now
   permits only the one-way `issued` to `redeemed` or `void` transition.

2. **P1 — quote items could be deleted after issue.** The item trigger covered
   update but not delete, allowing the persisted quote facts to diverge from
   the issued snapshot. Both update and delete are rejected.

3. **P1 — a quote could name a disabled or missing seller.** Publication
   rejected an inactive seller only indirectly at persistence time, while quote
   issuance trusted the stored identifier without checking the legal entity.
   Publication and issuance now both require an existing active seller and
   return the generic market-unavailable boundary.

4. **P2 — unknown device lock state passed an eSIM requirement.** A device that
   reported eSIM support but had never established whether it was unlocked was
   treated as eligible. Required unlocked-device rules now fail closed with
   `device_lock_not_checked`.

Regression tests cover all four findings, including direct PostgreSQL writes
against the immutable quote triggers.
