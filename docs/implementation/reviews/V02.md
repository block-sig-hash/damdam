## Findings and fixes

1. **P1 — provider commands could be repeated after a lost response.** The
   submitted lifecycle called the provider before durably recording dispatch,
   shared one hangup operation across distinct legs, and allowed a later worker
   to resend an ambiguous command. Operations are now committed before the
   external call, `dispatched_at` makes an unknown outcome non-retryable, and
   per-leg `target_key` values make each termination independently durable.

2. **P1 — authorization idempotency did not bind the full request.** A reused
   key could return a grant for changed duration, device credential, entitlement,
   identity or seller inputs, while concurrent first requests raced before the
   uniqueness check. PostgreSQL advisory locking now serializes a caller/key
   pair and every immutable authorization input must match the stored attempt.

3. **P1 — a guessed client correlation could authorize an unbound provider
   event.** An unknown leg could rely on `client_state` without corroborating
   the active device credential, provider connection, credential expiry and
   destination; known legs also tolerated conflicting identifiers. Events now
   bind through stored server-created operation state and quarantine every
   identity or destination mismatch.

4. **P1 — authenticated events were neither replayable nor sufficient to drive
   the call.** Only a reduced payload was retained, early events could be lost
   during reconciliation, and ordinary parked/answered/ended events required an
   unimplemented caller to issue the next command. The inbox now keeps the raw
   and normalized event, reconstructs the authenticated normalized form for
   replay, and advances destination creation, bridging and peer termination
   automatically under the durable stop guard.

5. **P1 — grant consumption trusted state that could change after
   authorization.** Membership, device credential, ownership, expiry,
   reservation and stop state were not all revalidated under lock. Start now
   locks and reloads the grant, checks every binding and the held reservation,
   and cannot cross a concurrent stop. Stopping an unused grant cancels it and
   releases its hold.

6. **P1 — client-session issuance could orphan or duplicate provider
   credentials.** The provider was called before a recoverable intent existed,
   every token refresh created another credential, and a lost first response
   was treated as safely retryable. Credentials now have explicit
   `provisioning`, `active`, `outcome_unknown` and `revoked` states; the issuance
   reference is committed before dispatch, an active device credential is
   reused for token refresh, and an ambiguous outcome is held for review.

7. **P1 — revocation and offboarding were incomplete.** Provider-first deletion
   could leave a credential locally active after a provider failure, while
   account recovery and membership removal did not reach calling state. Local
   revocation now commits before best-effort provider cleanup; account recovery
   revokes every device credential, and membership removal cancels work grants
   and durably requests hangup for the member's active work legs.

8. **P1 — route gating could both over-enable and disable containment.** The
   submitted settings permitted a live route in a non-test environment once
   configuration strings were present, despite the evidence gates remaining
   open. Conversely, switching new calls off selected a disabled adapter and
   also removed signed-event ingestion, credential revocation and hangup. Live
   routes now fail startup outside tests until later evidence-bearing work, while
   either configured control or verification key retains the Telnyx adapter for
   recovery with originate/session issuance still gated.

9. **P2 — the schema documentation omitted state needed to interpret durable
   records.** The model record now defines stop requests, per-target operation
   uniqueness, dispatch ambiguity, normalized event storage, non-revoked
   credential uniqueness and the provisioning/unknown issuance states.
