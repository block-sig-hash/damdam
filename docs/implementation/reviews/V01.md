## Findings and fixes

1. **P1 — the selected topology rejected a documented authorization hook.**
   The submitted API contract said a client-originated call had no
   pre-connection backend control. Telnyx's current Outbound Dialer and SIP
   Connection documentation explicitly describes Park Outbound Calls: ordinary
   WebRTC calls wait for backend instructions before the PSTN leg is created.
   The contract now selects that documented route for preparation and retains
   backend-originated calling as a conditional fallback.

2. **P1 — emergency calls bypass the proposed parking control.** Telnyx states
   that country-matched emergency calls are routed normally rather than parked.
   A copied credential could therefore bypass the assumed grant boundary.
   Emergency/special destinations are now a mandatory pre-SDK denial and an
   account-level containment test. The live route remains disabled until that
   test passes; the internet product makes no emergency-calling claim.

3. **P1 — webhook freshness and correlation were treated as authorization.**
   An Ed25519 signature plus timestamp tolerance accepts the same valid event
   again within the window. Base64 `client_state` has no integrity of its own,
   and public docs do not promise that independently originated legs share one
   `call_session_id`. V02 now requires a durable unique event inbox,
   authoritative attempt/leg mappings, provider-identifier validation and
   within-window replay tests.

4. **P1 — the cost model asserted an unevidenced $0.004/min floor and exact
   two-CDR settlement.** Telnyx publishes $0.002/min WebRTC and Voice API unit
   prices, but the public evidence does not settle how many of each component
   the candidate topologies incur or guarantee one shared CDR identifier. The
   model now represents component counts, durations, increments, fees and
   Nigeria rates symbolically and settles actual records through DamDam's
   durable leg mappings.

5. **P2 — credential ownership conflicted with Telnyx's device guidance.** The
   retained model permits one telephony credential per user. Telnyx recommends
   separate credentials per device, and sharing one SIP identity creates
   registration/revocation ambiguity. The reuse inventory and V02 proposal now
   require revocable per-device/browser credentials and short-lived client
   sessions.

6. **P2 — two required compatibility/adapter checks were incomplete.** The
   current Telnyx packages declare peer ranges that include RN 0.86 and React
   19, closing the documentation-only part of B5, while the vendor demo remains
   on RN 0.79.6 and calls for legacy peer resolution. Native builds and calls
   remain V04 evidence. The current official bridge material also disagrees on
   the peer-call request field; the existing adapter is classified for
   contract-probe refactoring instead of acceptance by assumption.

## Accepted contract

- V02 may implement provider-neutral authorization, per-device client sessions,
  durable operations, event ingestion, attempt/leg state and the negative-test
  matrix after its numbered prerequisites are accepted.
- The Telnyx parked topology is the documented preparation target. Provider
  live mode stays off until credential/emergency containment, event identity,
  parked-leg bounds and billing behavior pass account tests.
- Every server-created leg gets `time_limit_secs`; no hard-prepaid claim is
  made while the parked leg and termination delay lack a verified bound.
- Customer talk time and supplier invoice components remain separate.
