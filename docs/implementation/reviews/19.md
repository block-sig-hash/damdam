## Findings and fixes

1. **P1 — quote identifiers crossed account boundaries.** The submitted quote
   create/read endpoints did not bind a quote to the authenticated account, and
   the existing-intent resume path returned another payer's order before any
   ownership check. Consumer quote lines now name only the buyer, quote reads
   hide foreign ids as absent, and checkout verifies payer ownership before
   reading or reopening any payment attempt.

2. **P1 — a successful hosted checkout could not be reconciled reliably.** The
   accepted Paystack adapter requires the payer email, but checkout omitted it.
   The returned provider reference was also discarded and the attempt remained
   `created`, so a webhook using the provider's reference could not find the
   charge. Checkout now supplies the required email without copying it into
   provider metadata, persists the provider reference, marks the attempt
   pending, and resolves both success and failure events by that reference.

3. **P1 — processor and rail selection disagreed across endpoints.** Method
   discovery advertised card and bank transfer from a live merchant alone,
   including when no adapter or explicit rail existed, while checkout used the
   stricter payment router. Discovery now applies the same unique merchant,
   configured rail, live approval and adapter-name checks; checkout also
   refuses an adapter for a different processor.

4. **P1 — recovery was device-local and could invite a duplicate purchase.**
   Order responses exposed neither the originating quote nor the latest payment
   attempt. A second device therefore saw an unpaid order as never started, and
   pending/unknown screens offered a route back to browsing. The API now returns
   `quote_id` and authoritative attempt state; active payment and provisioning
   states have no dismissal-to-purchase action, while failed attempts retry the
   same quote and order.

5. **P1 — a shared phone could open the previous account's pending order.** The
   AsyncStorage record had no owner. It is now account-bound, ignored for every
   other account, conditionally mutated by account and order id, and cleared on
   every session-ending path. Ownerless records from older builds fail closed.

6. **P1 — browser-launch failures were silently treated as successful
   handoffs.** `Linking.openURL` was fire-and-forget and the record said payment
   had started before the OS accepted the URL. The order is now persisted first
   as not handed off, a successful launch advances that flag, and a rejected
   launch renders localized recovery while retaining the same server order.

7. **P1 — visited-network coverage was not a purchase gate.** A product with no
   coverage, or coverage only in a different country, could still be quoted.
   Browse and quote creation now require verified coverage for the selected
   country while still showing the complete coverage list before payment.

8. **P2 — terminal attempt failures were invisible to order status.** A failed
   processor attempt may leave the order's aggregate payment state `unpaid`.
   The client now uses the server attempt state to show decline/retry rather
   than indefinite confirmation. Active retries outrank older failed attempts
   even when the database clock gives them equal timestamps.

9. **P2 — method-discovery and unexpected client errors failed unsafe or leaked
   runtime text.** A failed method request could enable the pay button by
   omission, and non-API exceptions were shown untranslated. Unknown method
   state now disables collection, unexpected failures use first-party English
   and French copy, and payment-routing conflicts have localized 409 responses.
