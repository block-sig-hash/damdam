## Findings and fixes

1. **P1 — an expired worker could complete another worker's lease.** Completion
   and failure trusted a stale ORM object and did not verify current ownership.
   Every claim now has a unique lease token, preserved across ORM expiration;
   completion/failure lock the row and require the same unexpired token.

2. **P1 — terminal supplier outcomes were reversible.** A late rejection could
   downgrade an accepted purchase to failed, enabling another purchase. Result
   handling is now locked and terminal/idempotent, and PostgreSQL rejects any
   rewrite of an accepted or rejected attempt.

3. **P1 — attempt creation, cancellation and result handling raced.** These
   paths now lock the order item first and the attempt second. Concurrent
   workers converge on one attempt, while cancellation cannot cross an
   outstanding supplier request.

4. **P1 — duplicate inbox delivery rolled back unrelated caller work.** The
   uniqueness collision called `session.rollback()`, discarding the enclosing
   transaction. Duplicate detection now uses a nested savepoint.

5. **P2 — accepted results could omit their supplier reference.** The service
   now returns `accepted_result_missing_reference` before reaching the database
   constraint, and exact terminal replays remain harmless.

6. **P2 — outbox dedupe keys could silently change meaning.** Enqueue is
   serialized by logical key and verifies that an existing row has the same
   topic and payload. Claiming selects only one pending or actually expired row
   instead of locking and scanning live leases.
