## Findings and fixes

1. **P2 — malformed provider data escaped the contract boundary.** The submitted
   parsers accepted non-integer purchase quantities and malformed envelopes, and
   missing/null SIM status raised `TypeError` instead of the harness's declared
   `ContractViolation`. The reconciler could classify a zero-item request as
   complete. Request, response and reconciliation inputs now fail closed with
   consistent contract errors. Regression coverage includes booleans/floats,
   missing status, string tags and non-array response fields.

2. **P2 — live probe failures could emit tracebacks and account-specific
   details.** Network and response-shape failures were unhandled, and successful
   output printed provider resource IDs and partial ICCIDs even though it was
   described as pasteable evidence. The probe now validates an exact
   `damdam-op-<uuid>` lookup and a finite positive timeout, requests the maximum
   documented page size, redacts transport/contract failures, and emits only
   non-identifying status/type/voice fields.

3. **P2 — the written retry recipe was unsafe when read on its own.** API
   contracts §2.1 said an empty tag lookup proved the purchase had not landed
   and was safe to retry, while the following section correctly said lookup
   consistency is undocumented. The recipe now requires Telnyx confirmation of
   consistency and any settling window; until then, zero remains outcome
   unknown and requires manual review.

The dated claims were independently rechecked against current official Telnyx
documentation on 9 September 2026. The pages still describe VoLTE as beta,
native calling with an assigned E.164 number, one-time eSIM activation codes,
and the published eSIM purchase/list contracts. No official source found turns
the data footprint into a voice-coverage guarantee or supplies Nigeria mobile
voice rates. The capability matrix therefore remains conservative.
