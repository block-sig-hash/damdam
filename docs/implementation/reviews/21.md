## Findings and fixes

1. **P1 — the device list was disconnected from real authentication.** Login
   and refresh issuance never created or rotated `account_sessions`, so a real
   customer saw no device to revoke. Token issuance now projects sessions,
   access tokens identify their refresh session, rotation preserves one device
   row, and revoked, expired or removed tokens cannot remain visibly active.

2. **P1 — the mobile deletion confirmation did not delete anything.** It only
   cleared the handset cache and switched accounts. The flow now calls the
   authenticated deletion endpoint first, clears local state only after a 202,
   and stays signed in with cached data intact when the server refuses.

3. **P1 — deletion preflight was advisory rather than enforced.** The destructive
   endpoint did not repeat it, so callers could bypass every blocker. It now
   refuses unfinished payments/refunds, active personal or work entitlements,
   organization ownership with other active members, live calls and unsettled
   call charges, and revokes calling credentials before entering retention.

4. **P1 — the approved calling expansion was not connected.** Chunk 21 exposed
   a probe registry but V02/V03 contributed no probe, and exports omitted call
   history. The calling module now registers its liability checks at startup,
   while account exports include caller-owned attempts and charge state without
   credential or activation secrets.

5. **P1 — support ownership followed the payer rather than the service holder.**
   A work-service recipient could not reference their own line while its buyer
   could. Entitlement references are now authorized against the current holder.

6. **P1 — historical receipt descriptions came from the live catalog.** A
   product rename rewrote old receipts. Checkout now snapshots the product name;
   migration `0040_account_and_support` backfills existing order items and the
   receipt reader uses the frozen value.

7. **P1 — “sign out other devices” could sign out the current device.** The API
   did not expose current-session identity and the mobile action could not name
   the row to retain. New tokens carry an opaque session id, `is_current` is
   returned, the keep-current action is disabled when identity is unavailable,
   and deliberately revoking the current session clears the account cache and
   exits.

8. **P2 — the required My Line offline slices existed but were never used.**
   Timestamped usage/line state and installation confirmation are now written
   under the authenticated account id, read on network failure, visibly marked
   offline, and cleared by the existing account-prefix removal.

9. **P2 — migration and documentation identities collided with accepted voice
   work.** The account migration now follows `0039_call_settlement` as
   `0040_account_and_support`; the data-model amendment is §6.56 and the API
   amendment is §7.39. The generated OpenAPI document contains one integrated
   contract rather than choosing one side of the old conflict.

10. **P2 — several new refusal reasons fell back to generic mobile copy.**
    Pending payments, active services and settlement-pending calls now use their
    bilingual reason text, while unknown future codes retain the safe fallback.

11. **P2 — the PostgreSQL account fixtures made the review suite needlessly
    slow and encouraged misleading skipped runs.** They now use a module engine
    with isolated transactions/savepoints and unique identities. Review
    evidence below uses `TEST_DATABASE_URL`, the variable that actually enables
    these PostgreSQL-only tests.

## Remaining gates

- **Account export delivery is not implemented.** The owner-scoped domain
  builder and durable/idempotent request row exist, but no worker, approved
  private-object-storage configuration, status endpoint or authenticated
  download endpoint exists. A 202 therefore means “request recorded,” not “file
  will arrive.”
- **Commercial notification dispatch is not implemented.** Preferences and
  locale-bearing categories exist, and chunk 17 deduplicates low-balance
  thresholds, but no runtime scheduler/dispatcher consumes those rows for
  low-balance, expiry or order-status delivery. Preference controls must not be
  represented as completed notification delivery.
- No VoiceOver/TalkBack or physical-device account pass was run. Roles, labels,
  bilingual rendering and local persistence are covered by automated tests;
  hardware evidence remains a release/pilot activity.
- External D1–D5 gates remain unchanged. This review performs no live payment,
  carrier, calling, notification-vendor or production-storage operation.
