## Findings and fixes

1. **P1 — caller testimony could bypass supplier reconciliation.** The submitted
   request accepted a `reconciled` boolean. It is removed: the durable attempt
   must be `held_for_review` after the reconciler ran.

2. **P1 — a typed supplier reference could falsely provision service.** Success
   now requires a locally adopted carrier line with the same provider/reference;
   failure is refused when an adopted line already proves service exists.

3. **P1 — concurrent distinct-key decisions could both be recorded.** The
   attempt is reloaded under `FOR UPDATE` after the subject advisory lock. A
   two-session regression proves only one decision survives.

4. **P1 — the payment endpoint was an arbitrary balance-transfer primitive.**
   Debit account, amount, currency and date are no longer caller-controlled.
   They derive from the immutable receipt bound by an open
   `unmatched_bank_transfer` exception; the caller chooses only a same-currency,
   non-system customer service-credit account.

5. **P1 — accepted V02/V03 calling scope was absent.** A bounded call-charge
   correction endpoint now delegates to V03, preserves charge history, posts
   only the difference, binds the exact call exception and records one immutable
   operator action.

6. **P1 — arbitrary exception IDs could close unrelated work.** Resolution now
   requires the exact unresolved subject and expected kind. The audit foreign
   key uses `RESTRICT`, preserving its evidence link.

7. **P1 — dismissal could erase unresolved liability.** Payment, refund,
   dispute, settlement and every call-liability kind now require a real
   resolution workflow and cannot be dismissed.

8. **P1 — blank reasons could mutate state before validation.** Reasons are
   normalized and rejected before any mutation. A regression catches the error,
   commits the session and proves no state or audit row changed.

9. **P1 — idempotency keys could replay different evidence.** Supplier,
   payment, call, dismissal and sensitive-read replays compare their immutable
   evidence and return `idempotency_conflict` on mismatch. Monetary strings are
   canonicalized before call-correction comparison.

10. **P2 — dismissed queue work was undercounted.** `action_count` now follows
    either the exact exception foreign key or subject reference.

11. **P2 — migration/docs collided with accepted predecessors.** The migration
    is `0044_operator_actions`, following `0043_enterprise_offboarding`; the
    amendments are data-model §6.60 and API §7.43. OpenAPI was regenerated.
