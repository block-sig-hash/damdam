## Findings and fixes

1. **P1 — one idempotency key could represent every later call.** The client
   retained its pending placement after a successful authorization, so a later
   call to the same destination replayed the completed attempt and a different
   destination could conflict with it. The key is now retained only while the
   authorization outcome is ambiguous; a known authorization or terminal path
   starts the next placement with a fresh key.

2. **P1 — terminal and disposal paths could leave a server attempt live.** A
   local hangup did not enter the ended phase; adapter `ended`/`failed` events
   only changed the screen; and unmount/account switch disconnected without
   stopping a known attempt. Every terminal path now best-effort hangs up and
   acknowledges the server, including authorization that completes after the
   controller has been disposed.

3. **P1 — device credentials were scoped to the user, not the installation.**
   Production passed `currentUserId` as `deviceId`, collapsing every handset for
   a user onto one credential and revocation target. The app now derives a
   stable installation identifier from `react-native-device-info`, fails closed
   when it cannot obtain one, and reserves the prop override for tests/embedding.

4. **P1 — the claimed identity preview happened after commitment.** The screen
   learned the presentation number only from authorization, after the money
   hold already existed. The eligibility response now exposes the server-chosen
   `identity_e164` as an additive response-only field, and the client shows it
   alongside rate and payer before enabling placement.

5. **P2 — editing a destination temporarily enabled an unpriced call.** The
   previous eligibility object remained visible while a new request was in
   flight. Eligibility is now cleared on every destination/payer change, and
   placement additionally requires a settled quote for the exact destination.

## Remaining gates

- **D1 and B1–B5 remain OPEN:** no Telnyx account, WebRTC credentials, approved
  rate deck, cleared market, live containment evidence or physical device call
  exists. No fixture or Jest adapter is provider evidence.
- `resolveCallAdapter()` deliberately returns the unavailable adapter. A real
  SDK integration must supply outbound-only native permissions, split chunk
  04's retirement guard without restoring incoming calling, and pass supported
  iOS and Android builds.
- Backgrounding, screen lock, cellular interruption, network change, real DTMF,
  audio routing and server/provider cost agreement are unproven.
- The client currently uses `NGN` because the signed-in session contract carries
  no wallet currency. Multi-currency client selection requires a separate
  product/API decision.
