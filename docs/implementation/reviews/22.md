## Findings and fixes

1. **P1 — apply was described as resumable but committed only at request end.**
   A process death rolled back every row. Apply now locks the import, transitions
   it durably to `applying`, and commits each person, row outcome and counter
   update atomically before selecting the next row. A crash/reopen test proves
   that earlier rows survive and resume does not duplicate them.

2. **P1 — the dashboard had no usable individual-member authentication path.**
   `/people` depended on the retired shared-operator token convention. A new
   passwordless member login uses the existing identity API, derives the tenant
   from active server memberships, admits only owner/administrator roles, and
   persists no new session until organization authorization succeeds.

3. **P1 — different identifiers could silently merge people or end in a 500.**
   Matching stopped at employee reference, email or phone priority. It now
   resolves every supplied key and records `identity_collision` when those keys
   belong to different people, both during preview and if the conflict appears
   before apply.

4. **P1 — concurrent identical uploads raced between read and unique insert.**
   PostgreSQL transaction advisory locking now serializes the organization and
   digest pair; a two-thread test proves both callers converge on one import.

5. **P2 — every valid row was presented as a creation.** Preview now resolves
   the existing identities and reports distinct create and update forecasts;
   the dashboard renders both.

6. **P2 — accepted 5,000-row imports could not be fully listed or exported.**
   People, import rows and CSV export were capped at 200/500. Their limits now
   match the documented 5,000-row import ceiling, with a 501-person regression.

7. **P2 — membership/invitation views assigned to this chunk were absent.** The
   dashboard now presents active members and pending invitations in an Access
   tab separate from service recipients. The view is read-only; MFA-protected
   mutations remain the existing chunk 07 backend flows and are not claimed.

8. **P2 — the member login could leave a half-signed-in or stale-tenant browser.**
   It previously stored tokens before membership lookup and did not clear an
   old organization on refusal. Login now clears stale member state first and
   stores the session and selected tenant only after authorization succeeds.

9. **P2 — migration and documentation identities collided with accepted later
   work.** The integrated migration follows `0040_account_and_support` as
   `0041_organization_people`; the amendments are §6.57 and §7.40. Fresh upgrade,
   downgrade to 0040 and re-upgrade all pass with one Alembic head.
