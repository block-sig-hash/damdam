## Findings and fixes

1. **P1 — active purchase UI still sold retired safety behavior and promised
   the deferred Nigerian caller ID.** Package cards and the included-services
   panel advertised offline check-in/SOS, and the call copy promised the
   customer's Nigerian number. Those claims were removed; launch copy now
   describes a carrier-assigned number.

2. **P1 — the enterprise provisioning export still disclosed welfare data.**
   Its SQL loaded check-in and SOS records and exported their counts after the
   dashboard welfare screens had been removed. The queries, DTO fields and CSV
   columns were removed. A regression seeds historical welfare records and
   proves the export contains only name, phone, tier, purchase date and eSIM
   status.

3. **P2 — retired client code and native dependencies remained reachable.**
   The mobile API still exposed the geofence operation. Nitro SQLite,
   geolocation, background-fetch, UUID and SQL.js dependencies remained solely
   for removed safety queues. The API surface, mocks and dependencies were
   removed. Android activation notification copy was generalized and no longer
   implies a Saudi-arrival geofence.

4. **P2 — the dashboard still shipped its SOS browser-push worker and Firebase
   runtime.** The service worker, Firebase configuration, package and remaining
   SOS notification strings/styles were removed. A source-level regression
   protects that boundary.

5. **P2 — onboarding and purchase copy contradicted the reset.** The onboarding
   next-step promise to add family and departure details was replaced with the
   generic eSIM journey. Retired locale keys were removed in English and French.

6. **P2 — chunk 02's PNG integrity regression was intermittent.** `pngjs`
   sometimes accepted a file containing only IHDR and IEND. The validator now
   walks PNG chunk framing and requires a non-empty IDAT stream before decoding.
   The previously flaky test now passes deterministically in repeated local
   runs.

7. **P2 — the supplemental review workflow could not inspect large PRs.** It
   fetched the diff through GitHub's API, which rejects diffs over 20,000 lines;
   this branch is 29,415 lines. The workflow now resolves the base/head SHAs and
   generates the diff from the full local checkout, including its
   `issue_comment` fallback.

The submitted 410 responses, inert legacy Celery task names, removed schedules,
route/UI removal, read-only retention inventory and non-destructive data
boundary were retained. Check-in data remains because its final disposition is
still open; no schema or production data was deleted.
