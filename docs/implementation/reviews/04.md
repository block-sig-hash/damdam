## Findings and fixes

1. **P1 — production wiring dropped the account owner, disabling both
   queues.** `userId` was persisted during fresh authentication, but
   `toActiveSession()` discarded it on restore and `App.tsx` did not pass it to
   `AuthenticatedApp`. The outboxes therefore received an empty owner and
   refused every initialize/enqueue operation after a normal app boundary. The
   restore path now retains `userId`; the app passes it explicitly; and the
   authenticated component requires the prop even when an old stored session
   supplies `undefined`. A restart regression proves owner preservation.

2. **P2 — the claimed account-switch revalidation was constant in the real
   app.** `currentOwnerUserId: () => userId` captured the same render value as
   `ownerUserId`, so an old in-flight service could never observe a switch or
   unmount. A dedicated hook now shares a current-owner ref across replacement
   instances, handles React effect cleanup ordering, and invalidates ownership
   on unmount. Its integration regression retains the old A ownership object,
   switches to B, then unmounts and verifies each transition.

3. **P3 — whitespace was accepted as an owner.** Owner validation now rejects
   empty and whitespace-only identifiers. The change is defensive; normal
   server-issued IDs are UUID strings.

The submitted owner-scoped SQL, legacy-row quarantine, delayed-callback guard,
process-restart simulation and unchanged historical data are retained. The
client migration is additive and idempotent; no server migration or production
deletion occurs.
