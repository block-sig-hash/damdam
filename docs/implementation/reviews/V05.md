## Findings and fixes

1. **P1 — one idempotency key could represent every later browser call.** The
   controller retained its key after a known authorization and terminal event.
   Later calls could replay a completed attempt or conflict with a different
   destination. Keys now survive only an ambiguous authorization response; each
   later placement starts with a fresh key.

2. **P1 — provider and browser teardown paths left server attempts live.** Local
   hangup did not enter a terminal phase, provider `ended`/`failed` events only
   changed browser state, and disposal disconnected without acknowledging the
   attempt. These paths now hang up locally, stop server state, clear recovery
   storage and preserve final charge/history state.

3. **P1 — sign-out could lose the authority needed to release a late hold.**
   Calling API helpers read whichever consumer token happened to be in browser
   storage when an asynchronous step finished. Clearing or replacing the session
   could therefore abandon an authorization or authenticate teardown as another
   account. Each controller now captures its account token and supplies it to
   authorize/session/start/reconcile/stop calls, including disposal after storage
   has already been cleared.

4. **P1 — an offline refresh destroyed the recovery pointer.** Any reconciliation
   error erased the remembered attempt and rendered a fresh call surface, even
   though the old attempt could still be billable. Only definitive not-found or
   forbidden results clear it now; transient failures retain the id, block new
   placement and make Retry reconcile the same attempt.

5. **P1 — every browser owned by a user shared one credential identity.** V05
   passed the user id as `deviceId`, so revoking one browser described all of
   them. A non-secret random identifier now persists per browser across account
   sign-out. Missing durable storage or secure randomness fails closed.

6. **P1 — the presentation identity was not actually previewed before the hold.**
   After rebasing onto V04's accepted additive eligibility contract, the browser
   now displays its server-selected `identity_e164` with rate and payer before
   authorization.

7. **P2 — destination edits temporarily retained the previous quote.** A new
   number could leave the Call button enabled against an old rate. Pricing now
   clears the old result, and placement additionally requires a settled quote
   whose normalized destination exactly matches the input.

8. **P2 — French users requested an English sign-in message.** The page passed a
   hard-coded `en` to the identity endpoint. It now uses the selected client
   locale, with a regression for French delivery.

## Remaining gates

- **D1 and B1–B5 remain OPEN:** there is no Telnyx account, browser SDK,
  verified supported-browser matrix, approved rate deck, live credential
  containment, physical call, DTMF result or supplier charge comparison.
- `resolveCallAdapter()` deliberately returns the unavailable adapter. No jsdom
  or production-build result is evidence that media/signaling works.
- Browser pagehide is best effort and cannot be the spend bound. V03's durable
  server cutoff remains authoritative; real close/refresh/sleep/network behavior
  must be exercised with the selected SDK.
- The API's fail-closed origin configuration is accepted in chunks 25–26, but
  the exact deployed dashboard origin and copied-credential/provider containment
  remain environment and chunk 28 evidence.
- The browser uses `NGN` because the signed-in session contract exposes no
  wallet currency. Multi-currency selection requires a separate product/API
  decision.
