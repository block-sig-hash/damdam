## Findings and fixes

1. **P1 — mixed-currency order totals were possible despite AC-28.2.**
   `order_items.order_id` referenced only the order id, so a USD order could
   contain an NGN item and application code could add unlike amounts. Orders
   now expose a unique id/currency key and items reference both columns through
   a database foreign key. PostgreSQL rejects a mismatched item.

2. **P1 — settlement was absent despite AC-28.1.** Orders had only the customer
   charge currency and total. Nullable settlement currency and amount fields
   now form an atomic pair, may differ from the charge currency, and reject
   negative or malformed values. They remain null until settlement is known;
   chunk 14 owns detailed processor reconciliation.

3. **P2 — catalog prices allowed negative amounts.** A PostgreSQL check now
   rejects negative `product_prices.amount`, matching the existing order and
   item money invariants.

4. **P2 — the branch tracked an absolute local virtual-environment symlink.**
   `apps/api/.venv` pointed into the chunk 04 worktree and would be broken on
   every other machine. It was removed from Git; the repository already ignores
   local `.venv/` directories.

The Alembic migration and SQLModel metadata contain the same constraints.
Migration-level regression coverage checks the settlement columns and named
constraints after upgrading the real schema, while write tests prove
PostgreSQL refuses invalid values.
