## Findings and fixes

1. **P1 — reassignment exposed another holder's service state.** The submitted
   `/me/services` union retained every order item whose original recipient was
   the caller, even after its entitlement moved to somebody else. The former
   holder could still see the new holder's installation, activation and
   organization state. An unentitled pending purchase remains visible to its
   intended recipient, but once an entitlement exists its current holder is
   authoritative. Purchase history belongs to a later order/receipt view.

2. **P1 — unprovisioned carrier grants were reported as ready internet
   service.** Absence of a carrier line/installation was treated as proof of
   internet delivery. Before those rows exist, a normal eSIM entitlement
   therefore became usable immediately. Delivery now follows
   `DeviceEligibilityRule.requires_esim`, with existing carrier resources as
   corroboration and a safe carrier default for missing legacy rules.

3. **P1 — “sign in with a different account” did not sign out in memory.** It
   cleared the persisted session while `useSessionGate` retained an
   authenticated phase and the old account object, so the old app immediately
   rendered again. The session gate now owns sign-out, clears account-scoped
   PIN state, nulls memory and returns to onboarding while deliberately
   preserving the invitation being completed.

4. **P1 — existing phone-only accounts had no production sign-in route.** The
   handoff said `OnboardingNavigator` remained available, but the new root
   never mounted it. Email sign-in now offers an explicit phone/OTP route with
   back navigation, covered at the composed `AuthNavigator` boundary.

5. **P1 — cold/warm links could not reach JavaScript on a real build.** Android
   registered only the historical eSIM scheme and iOS registered no DamDam URL
   scheme or associated domain. Both native projects now declare the custom
   scheme and `damdam.app` web domains, with source-level regression tests.
   External Asset Links/AASA hosting is still correctly left to chunk 27.

6. **P1 — signed-out and email magic-link handling was incomplete.** Only the
   authenticated host subscribed to links, so a warm invitation while signed
   out was ignored, and “email me a link” worked only by manually pasting its
   token. The signed-out navigator now handles cold and warm purpose-bound
   login/recovery links and calls the matching endpoint; recovery cannot be
   downgraded to ordinary login.

7. **P1 — opening the sign-in email could erase the invitation that caused
   sign-in.** A single persisted slot meant a magic-link token overwrote the
   deferred invitation. Authentication links are now consumed directly while
   invitation/order/eSIM intents remain in platform secure storage for the
   authenticated host. The authenticated subscriber filters the process's
   already-consumed initial authentication URL before it can be resurrected.

8. **P2 — bearer invitation tokens were stored in plaintext AsyncStorage.**
   Pending intents now use the existing Keychain/Keystore dependency with a
   device-only, unlocked accessibility policy. This preserves the cross-auth
   journey without treating a membership credential like harmless UI state.

9. **P2 — required rendered states were absent from the screenshot matrix.**
   Consumer sign-in plus Home's no-service and load-error states are now
   registered in the harness and Maestro matrix in English and French. Generic
   network failures also render localized first-party copy rather than the
   runtime's untranslated error string.
