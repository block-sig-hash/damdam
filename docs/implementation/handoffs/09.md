### The design decisions later chunks must reuse

1. **Four countries are four columns.** Sales market, coverage, number country
   and call destination are separate tables. The one that matters most:
   aggregate supplier data coverage is *not* native-voice eligibility.
2. **Capabilities default to false.** An unverified capability is an absent one.
3. **Publication requires evidence, and a seller.** Two CHECK constraints, which
   is how D2 and D3 stop being paperwork.
4. **Quotes are immutable in the database.** Only `status` and `redeemed_at` may
   move.
5. **Rounding is the currency's exponent, half-to-even**, and an unknown
   currency raises rather than defaulting to two.

### Two things the work surfaced

- **The trigger changed the service.** `issue_quote` originally inserted an
  empty quote and then filled in the totals — which the immutability trigger
  correctly refused. It now builds the whole quote in memory and inserts once.
- **The digest had to normalise scale.** `Numeric(20, 6)` returns `1000.000000`
  for a quote issued as `1000.00`, so hashing raw values made every quote read
  as tampered after one round trip. Amounts are normalised to the currency
  exponent before hashing — still sensitive to the amount, no longer sensitive
  to storage scale.

Related, and worth a reviewer's eye: `ck_quotes_total_is_sum` and the digest
catch **different** things. The constraint proves the parts add up; the digest
proves they are the parts the server issued. A crude tamper never reaches the
digest, which is why the tamper test uses an internally consistent edit.
