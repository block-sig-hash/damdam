## Result and scope

The prior release-signoff validator already required a release-owner signature,
exact tested code/config ancestry, channel/scenario matrix and physical device
rows, but did not demand exact-head EAS or native CI references, physical
internal installations, disposition of blocking findings or founder-approved
pilot limits. It now rejects omitted/placeholder/blocked mandatory references,
EAS/native source SHAs that differ from the tested commit and any review status
other than `CLEAR`. All mandatory artifact, approval, channel-decision,
physical-device and passing-scenario references now require a strict digest
locator; the schema field binds the applied revision to one and must match the
tested commit's single connected, acyclic Alembic head. Operator fields use
opaque `owner:<32 lowercase hex>` roster identities; separate incident/support,
refund/finance and rollback-owner evidence locators are mandatory. A textual denial
or an unstructured build ID cannot satisfy the gate. The template tells the
release owner what to verify and explicitly limits what the validator can prove.

The [NO-GO dossier](../release/30-READINESS.md) records a provisional version
and schema inventory, open technical/external findings, role assignments still
needed, stop/rollback criteria and a gated rollout/store-asset checklist. It
does **not** create a release candidate, apply infrastructure or assert a live
pilot. The old chunk 29 EAS/Gradle signing compatibility risk remains open.
