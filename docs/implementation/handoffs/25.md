## Delivered surface

Eight admin-audience endpoints live under `/v1/operations`:

- searchable exception queue and immutable action history;
- supplier-attempt success/failure resolution;
- unmatched bank-receipt resolution to customer service credit;
- bounded call-charge correction through V03;
- dismissal for investigatory exceptions only;
- audited masked line lookup; and
- audited, tenant-scoped masked line export.

`operator_actions` records actor, reason, idempotency key, exact exception,
before/after state, and the journal entry when money moves. PostgreSQL prevents
updates and deletes. The migration is `0044_operator_actions`, following
`0043_enterprise_offboarding`; the data-model and API amendments are §§6.60 and
7.43.

## Safety boundaries

### Supplier decisions

The request has no `reconciled` assertion. The durable `SupplierAttempt` must
already be `held_for_review`, and the service reloads it under a row lock after
taking a subject advisory lock. A success requires a matching locally adopted
carrier line; a failure is refused if local adopted service already exists.
Concurrent operators with different keys cannot record two decisions.

### Payments

This is not a generic ledger-transfer endpoint. The request names only an open
`unmatched_bank_transfer` exception and the receiving customer service-credit
account. Its `bank:<receipt-id>` subject binds the immutable unmatched receipt,
which supplies amount, currency, value date and settlement-clearing account.
Receipt match, balanced journal entry, action and exception closure commit
together.

### Calling

A correction requires the exact open call exception and delegates to V03's
bounded replacement-charge service. The original charge remains immutable; only
the difference is posted, reservation bounds still apply, and the operations
action replaces the generic manual-correction exception as the audit record.

### Dismissal and sensitive data

Payment, refund, dispute, settlement and all call-liability exception kinds
cannot be dismissed. Looking up or exporting a line records an action. Returned
ICCID/E.164 values are masked, and activation material is absent from every
response schema.

### Replay and exception binding

Replays return the existing action only when reason, exact exception and action
evidence match. Reusing a key with different evidence returns
`idempotency_conflict`. An action cannot close an unrelated or already-resolved
exception. The exception foreign key is `RESTRICT`, because the evidence link is
part of the immutable audit record.
