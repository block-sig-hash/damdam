## Result

### AC-42.1 — the auth failure was one inconsistent clock

**Previous behavior.** `tests/test_auth_api.py::test_otp_request_and_verify_contract`
failed on every nightly inspected (2026-09-01 … 2026-09-08) with
`OTPError: invalid_refresh_token`, raised from a PyJWT `ExpiredSignatureError`.

**Diagnosis.** Not flakiness, and no code had changed. `TokenService.issue`
mints tokens against an **injected** clock, and `TokenService.decode_access`
already validates `exp` against that same injected clock — deliberately, with a
comment explaining that PyJWT's own `exp`/`iat` checks always use real
wall-clock time regardless of the `now` they receive. Two paths did not follow
that rule:

| Location | Defect |
|---|---|
| `apps/api/app/auth/routes.py` `refresh_token` | passed `datetime.now(timezone.utc)` instead of `app.state.clock()` |
| `apps/api/app/auth/tokens.py` `TokenService.rotate` | left PyJWT's `exp` verification enabled |

`tests/conftest.py`'s `MutableClock` is pinned to `2026-07-13`, so a refresh
token carried `exp` around `2026-08-12`. The test passed when written and began
failing the moment wall-clock time passed that date — the "July-versus-September"
mismatch. No rerun could ever have cleared it.

**Resulting behavior.** Both paths use the injected clock, matching
`decode_access`, `get_current_user` and `get_current_organization`.

**Production expiry is not weakened.** In production the injected clock *is*
wall-clock (`app.main.utc_now`), and `rotate` now enforces expiry **twice** —
against the token's own `exp` claim and against the stored `RefreshToken` row —
both compared against `now`. Signature and audience verification are untouched.

### AC-42.2 — the screenshot gate is now a matrix, not a count

**Previous behavior.** Both jobs ran `test "${#screenshots[@]}" -eq 32`. That
passes for any 32 PNGs: 32 copies of one screen, a set where an expected screen
is missing and an unrelated file makes up the number, or zero-byte, truncated
and non-PNG files.

**Resulting behavior.** `apps/mobile/scripts/validateScreenshots.js` requires the
exact expected set and inspects every image. The expected set is **derived from
the Maestro flows themselves** (`scripts/screenshotMatrix.js`): each
`takeScreenshot:` name is one expected image, and a flow's `tags:` decide which
platform runs it, mirroring Maestro's `--exclude-tags` selection.

- **No count is hardcoded anywhere.** Adding or removing a `takeScreenshot:`
  moves the gate. The derived matrix independently produces 32 per platform,
  16 flows each — which is how the previous hardcoded figure was *confirmed*
  rather than assumed, and it is not a target for the redesigned app.
- **The existing screen scope is unchanged.** No flow, screen or locale was
  added or removed; chunks 08 and 27 own the redesigned matrix.

### Refactoring concerns and tradeoffs for Codex

1. **Where `rotate` gets its expiry check.** I enforce expiry both on the JWT
   `exp` claim and on the stored `RefreshToken` row. The stored check alone would
   be sufficient and is the stronger authority (it also carries revocation).
   The doubled check is defence in depth against a row whose expiry drifts from
   the claim. If you consider it redundant, it is a safe deletion — but please
   keep one of them comparing against the *injected* clock.
2. **`get_current_organization` sets `verify_exp: False` but not
   `verify_iat: False`.** `decode_access` disables both, and its comment
   explains that PyJWT's `iat` check rejects a token minted at a mocked-*forward*
   clock. The HTO path is therefore latently exposed to the same class of bug —
   it does not bite today only because the test clock is in the past. I did not
   change it: it is not part of the reported failure, it is currently green, and
   widening an auth change beyond the diagnosed defect seemed worse than flagging
   it. Your call whether it belongs here or in chunk 06/07.
3. **The eslint override is a real config change.** `scripts/**/*.js` gets Node
   globals and `no-bitwise: off`. It is narrowly scoped and does not touch
   `src/**`, but it is a lint-rule relaxation and deserves a look.
4. **The validator is not a visual regression test**, deliberately. There are no
   committed baselines; inventing them now would either accept anything or
   reject every legitimate UI change. It cannot tell a correct screen from a
   structurally valid wrong one. If you think a baseline mechanism belongs here
   rather than in chunk 08/27, say so.
5. **`docs` path filter breadth.** It matches `docs/**` and `**/*.md`, so the
   link job runs on any markdown change anywhere. That is intentional — the
   checker validates the whole tree — but it does mean a README typo in
   `apps/mobile` triggers it.
6. **The 300000 ms timeout is a judgement call**, based on one healthy
   observation (~64s) and one failure (~156s). If a nightly still times out, the
   number is wrong or the cause is not slowness.
