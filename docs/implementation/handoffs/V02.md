## Result

### Previously

V01 produced a documented, reviewed provider contract and a go/no-go verdict —
GO for provider-neutral preparation, NO-GO for a live route — and no code. The
only calling code in the repository was `app/voice/`, the retired app-calling
feature whose historical `call_logs`, `voice_credentials`,
`verified_caller_identities` and `caller_id_consents` rows chunk 04 deliberately
kept. There was no way to authorize an outbound call, no model of a call attempt
distinct from a provider leg, and no durable record of a command sent to a
supplier.

### Now

A member can ask what a destination costs, be authorized for one specific call
against reserved funds, and have that call stopped and accounted for even when
the provider's side of the conversation misbehaves — while the route that would
put it on a wire stays off until the evidence exists to turn it on.

**API — new `app/calling` package (8 endpoints + 1 webhook):**

| Method | Path | What it does |
|---|---|---|
| `GET` | `/v1/calls/eligibility` | Authenticated rate/eligibility preview. Prices nothing it cannot price. |
| `POST` | `/v1/calls/client-session` | Short-lived, per-device provider credential. Rate limited. |
| `DELETE` | `/v1/calls/client-session` | Revokes one device's credential, alone. |
| `POST` | `/v1/calls/authorize` | Idempotent authorization. Reserves maximum exposure through chunk 10 first. |
| `POST` | `/v1/calls/{attempt_id}/start` | Spends the grant once and returns the start instruction. |
| `POST` | `/v1/calls/{attempt_id}/stop` | Terminates; survives a lost provider response. |
| `GET` | `/v1/calls/{attempt_id}` | Owner-scoped status. |
| `GET` | `/v1/calls` | Owner-scoped history. |
| `POST` | webhook | Signature/timestamp verified against the **raw** payload, deduplicated by provider event id. |

Plus the wiring in `main.py`: `CallAuthorizationService`, `ClientSessionService`
and `CallLifecycleService` on `api.state`, an adapter that is
`TelnyxCallingAdapter` **only** when the live route is explicitly enabled and
`DisabledCallingAdapter` otherwise, and error handlers mapping each domain code
to a status (`410` for an expired grant, `409` for an idempotency conflict, a
refused destination or insufficient funds, `503` for a disabled route).

**Schema — migration `0038_call_authorization`, five new tables:**
`call_attempts` (the grant), `call_legs` (provider legs, counted separately),
`call_operations` (every command, written and committed before it is sent),
`call_events` (the signed inbox) and `calling_client_credentials` (one per
device). Purely additive; two existing enums (`voice_origin_kind`,
`voice_destination_kind`) are **reused, not redefined**, so a rate and the call
it priced cannot disagree about what "mobile" means.

**Configuration — six settings, all off by default:**
`CALLING_LIVE_ROUTES_ENABLED`, `CALLING_CONTAINMENT_EVIDENCE_REFERENCE`,
`CALLING_SUPPORTED_DESTINATION_COUNTRIES`, `CALLING_GRANT_TTL_SECONDS` (120),
`CALLING_MAX_CALL_SECONDS` (3600), `CALLING_SESSIONS_PER_DEVICE_PER_HOUR` (20),
`CALLING_OUTBOUND_IDENTITY_E164`.

**The decisions a reviewer should look at:**

1. **A flag alone cannot put billable calls on a wire.** Setting
   `CALLING_LIVE_ROUTES_ENABLED` without the provider credentials *and* a named
   containment-evidence artifact fails at **startup**, not at the first call.
   `VOICE-EXPANSION.md` is explicit that UI feature flags alone cannot enable an
   unsupported service; B1 is open, so the route asks for the artifact by name.
2. **Destinations are refused before the SDK is touched.** `policy.py` is pure
   and does its work at authorization time, because V01 §2 found that Telnyx
   parks ordinary client-originated calls for backend authorization but **routes
   what it classifies as emergency calls normally**. For that one class of
   number the backend's later decision point does not exist, so a rule that
   needed a database round trip would be a rule somebody skips on a fast path.
   This reduces exposure; it does not close the gate (see *Known gaps*).
3. **One credential per device, not per user.** The retired model gave each
   *user* one credential, which makes revocation useless in practice — signing
   out a lost phone signs out every device the customer owns, so nobody ever
   does it. Sessions are short-lived tokens bounded by the credential's own
   stated expiry; the account API key never leaves the server. V01 established
   that a Telnyx JWT carries no per-destination scope, so a leaked long-lived
   one is a funded dialler.
4. **The ingestion path is always the same five steps:** authenticate inside the
   adapter before parsing, store by unique provider event id before deciding
   anything, resolve the attempt from *our* tables (`client_state` may point, it
   may not authorize), validate connection/credential/transition against the
   stored grant and quarantine a mismatch, then apply forward-only. Duplicated,
   delayed, reordered and unknown-leg events are each a documented V01 failure
   mode, not a hypothetical.
5. **Commands follow chunk 11's outbox discipline.** The operation row is
   committed *before* the provider is called, so a lost response has a durable
   thing to ask about. Reconciliation asks "what did operation X produce" and
   never "has enough time passed to try again" — that second question has
   produced a second billable call every time.
6. **Reservation is retail exposure, rounded asymmetrically.** Under-reserving
   surfaces at settlement when the money is already spent, which is how a
   prepaid product goes negative; over-reserving is recoverable the moment the
   call ends. Supplier cost is a different number and V03 owns it.
7. **`app/calling` is a new package, not an edit to `app/voice`.**
   `LEGACY-REUSE.md` classifies that module component by component: five
   primitives reused, eight refactored before use, seven rejected outright. A
   copied credential model, package-minute billing and the verified-CLI
   eligibility path are all one careless import away inside a shared module.

**Deliberately deferred:** settlement and enforcement (V03), the mobile and
browser clients (V04/V05), own-number presentation, and browser origin policy
(chunks 25/26).

## Known gaps and handoff

- **B1 — credential containment is unproven, and this is the one that matters.**
  Nothing here stops a copied token from reaching the provider's emergency flow,
  because that flow bypasses the parking hook the design depends on. The refusal
  implemented in `policy.py` is ours, at authorization time; a client that never
  calls our API is not subject to it. Only an account-level test closes this.
- **B3 — the parked client leg has no documented duration bound.**
  `time_limit_secs` bounds the destination leg we create and is the only control
  that survives this process dying. **No hard prepaid guarantee is made**; the
  daily spend limit is a backstop with no documented reaction time.
- **Reconciliation has a deliberate dead end.** Telnyx documents no lookup by
  `command_id`, so `reconcile_operation` returns `None` and the operation is
  held for human review rather than retried. A worker that retried would dial a
  second billable leg.
- **F2 — the bridge field name is unsettled** until the prepared contract probe
  is sent.
- **Event identity assumption.** Telnyx's `data.id` is the deduplication key. If
  an account test shows it is not unique per delivery, the inbox key is wrong,
  and `telnyx.py` is where that changes.
- **V03 owns settlement.** Reservations are held and released here; nothing is
  captured, and supplier cost is not reconciled. The number of billable supplier
  components per call is unproven for this topology (V01 §8).
- **For Codex:** the tradeoff worth arguing about is `policy.py` being pure and
  duplicating a slice of tariff knowledge that `app/catalog/tariffs` also holds.
  The duplication is intentional — a refusal must be computable without a
  database — but if it drifts, a destination could be refused at authorization
  and priced differently at preview.
- **No merge, deployment, store submission or production deletion was
  performed**, and none is authorized by this assignment.
