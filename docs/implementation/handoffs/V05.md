internal staff (`/admin`), and a consumer had no way to call from a browser.

**Now** `/calls` is a consumer calling area with its own credential, its own

### Privilege separation is an absence, not a check

`/calls` reads `damdam_consumer_access_token` and nothing else. The operator
token (`hto_access_token`) and the admin token (`admin_access_token`) are never
read by any code on this path, so an internal user who opens the page is *signed
out*, not elevated — there is no branch that could fall back to them. A role
check can be widened by a later edit; a token this code never reads cannot be.
Three tests assert it by putting each of those tokens in storage and checking
the visitor is still asked to sign in.

Sign-in is chunk 06's email-identity path, which a staff credential cannot
satisfy: somebody with admin access who wants a personal call signs in as
themselves.

### The browser-specific rules

- **A refresh reconciles; it never redials.** The live attempt lives on the
  server and is remembered here by **attempt id alone**. On mount the page asks
  the server what that attempt is doing. Refresh, a restored or duplicated tab
  that carries the scoped storage, and a machine waking from sleep are the same
  question and get the same answer. A fresh independent tab remains signed out.
  Redialling would be a second call and a second charge for one thing the
  customer did once — the most likely way a browser client bills twice.
- **Unload is best effort and is not the spending control.** `releaseOnUnload`
  tries, and swallows every failure, because a page being torn down may never
  finish a request. What actually bounds the spend is V03's server-side cutoff,
  which does not depend on this code running. The in-call panel says so.
- **`sessionStorage`, not `localStorage`.** A calling credential should not
  survive a closed browser on a shared machine, and a second tab should start
  signed out rather than inherit a call.
- **No refresh token is stored**, so the grant cannot be silently renewed.
- **Sign-out clears the remembered attempt id**, or the next person on that
  browser could reconcile — and be shown the cost of — somebody else's call.
  Teardown retains the controller's captured token long enough to stop its own
  attempt; it can never authenticate the stop as the next signed-in user.

### Credential handling

The only credential-shaped thing that reaches this app is the short-lived
per-device session from `POST /calls/client-session`. There is no Telnyx API
key and no SIP password in the source, the bundle or any storage — the account
key never leaves the server, which is V02's design and unchanged here. Requests
use `credentials: "omit"`: the API is a separate origin authorizing by bearer
token, so no cookie is sent and there is no CSRF surface on this path.

## Known gaps and handoff

- **The SDK is not integrated and no live call is claimed.** `resolveCallAdapter()`
  returns an adapter that advertises nothing and refuses to connect. **D1 is
  open** — no Telnyx account — and V01's B1–B5 stand. **Exact missing input: a
  Telnyx account with WebRTC credentials (owner: founder).** Live microphone,
  audio, DTMF, identity and actual-charge proof on supported browsers remains
  pending and is distinct from every mocked test above.
- **The supported-browser matrix is unknown.** `mediaSupport()` detects capture
  support and insecure contexts, which is real and useful, but which browsers
  and versions actually carry a call end to end is exactly what V01 could not
  establish. The page reports what it can detect and claims nothing more.
- **Unauthorized origins and copied-token abuse are server-side properties.**
  Accepted chunks 25–26 own the fail-closed CORS configuration and V02 covers
  foreign-attempt ownership. This chunk does not prove a deployed origin or
  provider-side containment; V01 B1 and chunk 28's copied-credential scenario
  remain open.
- **The call currency is a constant (`NGN`)**, for the same reason as V04: no
  session endpoint reports one and chunk 09 has a single supported market. A
  multi-currency account needs the server to say which currency the caller
  spends.
- **Calling credentials use a stable browser identifier.** It is a non-secret,
  random local-storage value that survives account sign-out, while bearer tokens
  and remembered attempts remain tab-scoped and are cleared. If durable storage
  or secure randomness is unavailable, placement fails closed.
- **The browser session controller duplicates the mobile one.** The two apps
  share no build today and creating a workspace package to hold ~200 lines would
  be a larger change than the duplication it removes. Worth revisiting when a
  third client appears — flagged for Codex as a deliberate tradeoff rather than
  an oversight.
- **Cross-client spend tests (V04 + V05 against one balance) belong to chunk 28**,
  as the assignment says, and are not attempted here.
- **No merge, deployment, store submission, vendor message, live purchase or
  production deletion was performed.**
