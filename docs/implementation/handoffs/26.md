## Result

### 26A — correlation and redaction-safe structured logs

`app/observability.py`. Every response now carries `X-Correlation-Id`; a
client's own id is kept when it is safe, generated otherwise. The id lives in a
`ContextVar` so a service five frames down can log it without it being threaded
through signatures that have no other reason to know about it.

**Redaction is a `logging.Filter` on the root logger, not a helper.** A helper
that callers must remember to call is forgotten exactly once — in the path that
logs a full activation code. As a filter it also covers libraries we did not
write and did not audit, which is where a request body gets logged on debug.

Request logs name the **route template**, not the path: `/v1/calls/{attempt_id}`
rather than a line per attempt id. Raw paths carry customer identifiers into log
search and make every route unique.

The middleware is pure ASGI rather than `BaseHTTPMiddleware`, which wraps the
request in an anonymous task where a `ContextVar` is not reliably visible to the
endpoint — a failure that is silent and only appears under load.

### 26B — production refuses developer defaults

`APP_ENV=production` now fails **at startup** on: the published development JWT
secret; an unset mail provider; an `http://` or localhost browser origin; an
unsigned call-event configuration when live routes are on; and a
`METRICS_SCRAPE_TOKEN` shorter than 32 characters.

Browser origins are now a configured list (`DASHBOARD_BASE_URL` +
`ADDITIONAL_BROWSER_ORIGINS`), which closes the CORS gap V05's handoff flagged
as belonging to this chunk. `security.md`'s V02/V03 amendment assigns browser
origin policy to chunks 25–26; this is 26's half. Secret *rotation* is 26D.

### 26C — the five numbers somebody is woken up for

`app/metrics.py` plus `GET /v1/admin/metrics` (Prometheus) and
`/v1/admin/metrics.json`. Oldest unprovisioned order, unknown supplier
outcomes, unknown **call** outcomes, webhook lag, quarantined and unmatched
events, usage staleness, and open exceptions by kind.

Carrier and calling failures are separate series, as the calling amendment
requires. Absence is reported as absence — a missing value is omitted from the
Prometheus output rather than exported as `0`.

A scraper gets its own `METRICS_SCRAPE_TOKEN` rather than an operator login,
compared in constant time.

## Findings from writing it

Two defects were found by the tests rather than by reading, and both are the
kind that fail silently:

1. **The redaction key pattern was anchored on `\b`, which does not fire inside
   `refresh_token`** — `_` is a word character, so there is no boundary between
   `refresh` and `token`. A boundary-anchored pattern silently misses every
   snake_case key, which is most keys in this codebase. Now matched as
   substrings. `idempotency_key` is deliberately exempt: it authorizes nothing
   and it is the field an engineer correlates on when investigating a suspected
   double charge.
2. **`configure_logging` removed every root handler**, which is correct in
   production — where it runs once — and quietly destructive everywhere else.
   Under pytest it removed the capture handler and blinded log assertions in
   every test that ran afterwards; a log shipper's or supervisor's handler would
   have gone the same way. It now replaces only handlers it installed. This was
   caught because two tests passed in isolation and failed in the full suite.
   It also set the root *level* and never restored it — harmless in a process
   that calls it once at startup, wrong to leave behind for a test session.

### One thing not fully explained, and how it was handled

Two middleware tests using `caplog` captured **zero** records in the full suite
while passing in isolation and alongside every subset tried (74 tests across
five files). A logging-state probe after a heavy suite showed nothing anomalous:
no `logging.disable`, no broken propagation, no unexpected level or handler.

They were rewritten to attach their own handler to a uniquely-named logger
rather than to rely on `caplog`. That is the better test regardless: `caplog`
binds to the root logger and depends on global logging state surviving a
thousand other tests, which is a flaky dependency by construction, and the
replacement asserts against the real `LogRecord` the middleware emits — it also
now checks the correlation id is present on a failed request, which the previous
version did not.

**The underlying interaction was not isolated.** Reproducer for anyone who wants
to chase it: run the full API suite with a `caplog`-based assertion on the
`damdam.request` logger. Nothing in application code calls `logging.disable`,
`basicConfig` or `dictConfig`, so the cause is a third-party import.

A third, found by reading: **`NullDeliveryTransport` discards identity email
silently.** Correct in staging, and in production a total authentication outage
that reports itself as healthy — every sign-in link goes nowhere and nothing
logs an error, because nothing failed. 26B refuses to start without a provider.

## Migrations and compatibility

- **No migration.** No schema change, no data touched.
- **No dependency added.**
- **New settings**, all defaulted so existing deployments are unaffected:
  `ADDITIONAL_BROWSER_ORIGINS`, `METRICS_SCRAPE_TOKEN`.
- **Behaviour change for existing deployments:** an `APP_ENV=production`
  deployment that today runs on the default JWT secret or without a mail
  provider **will stop starting**. That is the intent, and it is a deliberate
  breaking change to catch before a customer does; it needs naming in the
  release notes rather than discovering on deploy.
- **Rollback:** revert; nothing persists.
