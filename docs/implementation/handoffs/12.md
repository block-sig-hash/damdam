### Decisions later chunks must reuse

1. **Intent and attempt are separate.** One intent per order, several attempts
   allowed. That separation is what makes double-capture *detectable* rather
   than two uncorrelated payments.
2. **`ux_payment_attempts_one_success`** — at most one succeeded attempt per
   intent, in the database.
3. **Excess is recorded, never dropped.** An unmatched charge becomes an
   `excess_payments` row. The money has already left the customer's account;
   refusing to write it down would be losing it.
4. **A redirect cannot mark an order paid.** `PaymentState.PAID` is assigned in
   exactly one place, and a test asserts that.
5. **Routing uses seller, currency and method** — never nationality or IP.

### Paystack

NGN only, refusing any other currency rather than converting. The amount is sent
in the currency's minor unit with the exponent **derived** from `app/money.py`
rather than hardcoded as 100 — that error is a silent hundredfold mispricing,
and a mock built from the same assumption would agree with it.

Vendor claims are cited: endpoints, minor-unit convention and the
`x-paystack-signature` HMAC SHA-512 scheme come from Paystack's public API
reference, **checked 10 September 2026**. **No live or sandbox call has been
made from this branch**, and the adapter tests are not evidence that Paystack
behaves as documented.

### One thing this chunk fixed for the whole repository

`SQLModel.metadata.create_all` was quietly dependent on which model modules a
caller happened to import: a test touching payments failed on `quotes`, fixing
that failed on `sales_markets`, and so on down a chain nobody chose.
`app/model_registry.py` imports every model module in one place, with one
reason, so there is no chain to chase. Tests import it before `create_all`.

   retaining Flutterwave, so porting it would be adding scope.
