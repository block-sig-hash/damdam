### The finding the design turns on

A Telnyx WebRTC credential or JWT authenticates an **endpoint**. Having checked
the credential and JWT documentation, **no per-destination scope, claim or
allowed-list on the token is documented anywhere.** Under the approved plan's
rule that unknown means unavailable, the token must be assumed to authorise
dialling whatever its connection permits.

That makes the obvious design unacceptable: if the client hands a destination to
the SDK, a copied token becomes a funded dialler.

### Chosen topology

The backend originates **both** legs and bridges them. The client registers and
answers; it never names a destination.

This is possible because `Dial` accepts a **SIP URI** as `to`
(`sip:username@sip.telnyx.com;secure=srtp`), so the backend can dial its own
WebRTC client as leg A, then dial the destination as leg B.

The alternative — client dials, server vetoes via webhook — is **rejected
because no such pre-authorisation hook is documented.** The assignment
explicitly forbids inventing one, and this is where that would have happened.

### Controls, and their honest limits

| Control | Evidenced behaviour | Limit worth stating |
|---|---|---|
| `time_limit_secs` | Terminates a leg; `hangup_cause=time_limit`; from answer; max 14400 s | The **only** bound that survives the backend dying mid-call |
| Outbound Voice Profile | Allowed destinations, channel limit, daily spend limit, max per-minute rate | Whether a profile may have **zero** destinations is undocumented — blocker B1 |
| `command_id` | Dedupes duplicate commands | **Only within 60 seconds.** A later retry is not deduplicated; V02 needs its own idempotency key |
| Daily spend limit | Blocks outbound once exceeded | **No documented reaction time**, so it cannot back a hard prepaid promise |

### Evidence limitations — read before relying on anything here

1. **Every capability marked DOCUMENTED is a reading of a public web page on
   2026-09-09**, not a tested behaviour. Documentation and production behaviour
   diverge, and Telnyx's own VoLTE beta status is already an example.
2. **No account exists.** Nothing was confirmed with Telnyx, and no rate was
   retrieved: `GET /v2/public/pricing` returned **HTTP 404** unauthenticated.
3. **No SDK was installed and no call was placed**, so no latency, audio-quality
   or permission behaviour is known.
4. The credential-scope finding is an **absence** of documentation, not a
   documented prohibition. It is the strongest available conclusion from public
   sources, and it is exactly the sort of thing an account holder could disprove
   in five minutes. B1 exists to force that check.

## Notes for Codex

1. **The rejected alternative is the part most worth challenging.** If a
   pre-authorisation hook does exist and I missed it, the simpler client-dials
   design becomes viable and this contract should change.
2. **`LEGACY-REUSE.md` item 3 is the highest-value correction** — every retained
   billing path charges one leg, and the evidenced reality is two CDRs. Carrying
   that assumption into V03 would misprice every call.
3. **I did not fetch the RN SDK's own compatibility matrix.** B5 is stated as
   unknown rather than researched to conclusion; it does not gate V02/V03, but
   it should be closed before V04 is scheduled.
4. **The cost model's worked example uses a hypothetical $0.05/min** purely to
   show sensitivity. It is labelled as not an estimate, but if that risks being
   read as a rate, it should be cut.
