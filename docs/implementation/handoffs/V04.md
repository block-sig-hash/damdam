## Result

**Previously** the mobile app had four tabs and no way to place a call. V02 and
V03 had built and had accepted the entire backend — authorization, durable call
control, per-device credentials, metering, settlement and enforcement — and
nothing on a handset could reach it.

**Now** there is a Calls tab wired to that accepted contract, a provider
boundary for a calling SDK, and a session controller that holds the money rules.

### The rules the controller holds

1. **The microphone is asked for before the hold is taken.** A customer who
   declines the prompt after authorization has money reserved against a call
   that never dialled, released only when an expiry sweep runs.
2. **One placement is one hold.** A double tap, a re-render and a retry after a
   lost response all reuse the same idempotency key, so the server converges on
   one attempt.
3. **A client that gives up says so.** Every path that abandons an authorized
   attempt calls `stopCall`, including when the adapter throws on dial and when
   it throws on hangup. V03's own cutoff still runs if the process dies; this is
   the courteous path, not the guarantee.
4. **A disposed session is inert.** Switching account bumps a generation, and
   callbacks still queued inside an SDK land on a generation that no longer
   matches. Disposal also hangs up and stops a known live attempt. The next user
   cannot see or end the previous user's call.

### Carrier versus internet, stated rather than inferred

The screen names the mode and says, in words, that a carrier call is placed by
the phone's own dialler and that DamDam cannot start one. Nothing on this path
touches SIM selection, and changing the payer does not and cannot change which
SIM a carrier call would use. Choosing a work payer discloses that the
organization can see the call happened, its length and its cost — and not what
was said — before the call, not after.

### An internet-only customer needs no eSIM

Calls is a peer of Plans and My Line rather than a section inside it, and
nothing on the path consults an installation, an entitlement or a line. A test
asserts the whole journey — rate preview, call, history — with no eSIM anywhere
in it.

## Known gaps and handoff

- **The SDK is not integrated, and no live call is claimed.** `resolveCallAdapter()`
  returns `UnavailableCallAdapter`, which advertises no capabilities and refuses
  to connect. This is the honest state: **D1 is open** — there is no Telnyx
  account — and V01's B1–B5 blockers stand. A stub that resolved would have made
  every screen look finished and would be exactly the "mock passing itself off
  as evidence" the test policy forbids. **Exact missing input: a Telnyx account
  with WebRTC credentials (owner: founder), plus authorized iOS and Android
  devices.**
- **The microphone permission is implemented but cannot succeed.** Android
  `RECORD_AUDIO` is deliberately still absent from the manifest — chunk 08 left
  it out because requesting a permission the product cannot use trains people to
  decline it, and chunk 04's guard asserts its absence. iOS has no React Native
  microphone API at all: `AVAudioSession` raises that prompt, which means the
  SDK raises it. Both arrive together. `requestMicrophone` reports `blocked`
  rather than pretending, and the controller refuses before the prompt when no
  adapter can dial.
- **Chunk 04's retirement guard will need an intentional amendment when the SDK
  lands.** It asserts the absence of `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS` and
  `FOREGROUND_SERVICE_PHONE_CALL`. Outbound internet calling is an approved
  scope change under `VOICE-EXPANSION.md`, but *incoming* ringing is still
  retired, so the guard should be split rather than relaxed: keep `voip`
  background mode, PushKit and the contacts/location permissions asserted absent,
  and allow only what outbound audio needs. **I did not touch it in this chunk**,
  because amending a retirement guard without the code that justifies it is how
  a guard quietly stops guarding.
- **Lifecycle behaviour is disclosed, not proven.** `backgroundCall` is `false`
  for every adapter and the in-call panel says audio may stop if the app is
  backgrounded or the screen locked. App switch, screen lock, interruption by a
  cellular call and network change are **untested against any SDK** and remain
  open. The server-side cutoff continuing when the client dies is V03's, and is
  covered by V03's own evidence rather than claimed here.
- **The call currency is a constant (`NGN`).** `/me/session` carries no currency
  and chunk 09 has one supported market, so there is nothing to derive it from
  that would not be a guess. A multi-currency account needs the server to say
  which currency this caller spends; pricing a call against the wrong balance is
  the failure this would cause.
- **Calling credentials use the installation identifier.** The reviewed client
  derives it from `react-native-device-info` and refuses to mint a credential if
  the identifier is missing, rather than collapsing every handset owned by one
  user onto the user id. Device-scoped revocation therefore names one
  installation as the server contract requires.
- **No merge, deployment, store submission, vendor message, live purchase or
  production deletion was performed.**
