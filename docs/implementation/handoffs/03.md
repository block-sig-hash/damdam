### The findings that matter

1. **Voice coverage is entirely undocumented.** The "650+ networks / 180+
   countries" figures appear only on data pages and are qualified as "5G & 4G
   (LTE) networks". The VoLTE pages carry no coverage figure, country list,
   roaming statement or device matrix. Reading the data footprint as the voice
   footprint is the central mistake available here and nothing published
   supports it.
2. **VoLTE is still beta**, verbatim: "VoLTE is in beta. API reference and
   detailed configuration docs coming soon." The voice endpoints are *named* but
   their request/response schemas are not published, so they are deliberately
   not modelled in the harness.
3. **No mobile-voice per-minute rate is published at all** — not for Nigeria,
   not for anywhere. `telnyx.com/pricing.md` has none; `pricing/mobile-voice`
   shows only US carrier data fees and directs to sales. Launch pricing cannot
   be derived from public sources.
4. **No voice spending cap is documented.** Data has a supplier-side
   `data_limit` with unquantified enforcement latency; voice has no documented
   equivalent. This is in direct tension with the prepaid promise (D5) and with
   `prd.md` AC-36.4.
5. **eSIM activation codes are one-time use** — "If the device loses the
   profile, you need a new eSIM purchase — you can't re-download the same
   profile." Device replacement and account recovery must be built on
   replacement, not restoration. This independently confirms the chunk 01
   review's finding 7 against the vendor's own documentation.
6. **The product is framed as IoT.** Every device guide is a router or dev board
   — Raspberry Pi, Sixfab, Cradlepoint, Pepwave, MikroTik, Nordic, Particle.
   There is no consumer-smartphone VoLTE guide.
7. **Messaging is "coming soon"** on cellular numbers. Keep it out of scope; do
   not design any flow depending on SMS to the assigned number.
8. **`POST /actions/purchase/esims` has no idempotency key.** `tags` plus
   `GET /sim_cards?filter[tags][]=` is the only documented reconciliation path,
   and **its post-purchase consistency is itself undocumented** — see the
   tradeoff note below.

### Refactoring concerns and tradeoffs for Codex

1. **`lookup_is_trusted` is the load-bearing decision in this chunk.** Telnyx
   does not document whether a just-purchased eSIM is immediately visible to
   `filter[tags]`. If it is not, an empty lookup is indistinguishable from "the
   purchase never landed" — and retrying on that would double-purchase, the
   exact defect finding 4 describes. I default it to `False`, which escalates to
   manual reconciliation. That is deliberately conservative and will produce
   operational toil until it is proven live. If you think the default should be
   the other way, that is a real disagreement worth having — but it should be
   decided with evidence, not convenience.
2. **The tag pattern is reconciliation, not idempotency.** A retry issued before
   the lookup still double-purchases. The safeguard has to live in chunk 11's
   order state machine; this harness cannot provide it.
3. **Harness placement.** `apps/api/tools/` keeps it out of `app/` and out of
   coverage, but it is inside the API's ruff scope, so it must stay lint-clean.
   It is not in CI's mypy scope; I ran strict mypy on it manually and it passes.
   Adding `tools` to the mypy path would be a small CI change — chunk 02 or 26's
   call, not mine.
4. **`SimCard.from_payload` accepts status as either a bare string or an object.**
   Telnyx's schema shows a `$ref` and its examples vary, and I could not
   determine which the live API returns. Accepting both is defensive; if you
   consider it over-permissive, the alternative is to pick one and risk a parse
   failure on first contact.
5. **The capability matrix will go stale.** It is dated and carries reproduction
   commands, but a beta product's documentation moves. Re-date before
   contracting rather than trusting it.
6. **Nothing here should be treated as supplier evidence**, including the 35
   passing tests. If any later chunk cites this harness as proof Telnyx works,
   that is a review finding.
